# 스터디 시간 기록 — 설계 문서

작성일: 2026-08-21
상태: 설계 확정 (구현 계획 대기)
대상: `dongbang-booking` 앱에 기능으로 추가

## 1. 목적

HEVEN 전기팀의 개별 스터디 시간을 자동으로 기록한다. 현재는 `2026 스터디 참여시간.xlsx`를 수동으로 갱신하는데, 시작·종료 시각이 사후 자기신고라 부정확하고 집계가 사람 손을 탄다.

기록된 시간은 **영광 대회 엔트리 순서를 결정하는 근거**로 쓰인다. 즉 이 시스템의 출력은 단순 통계가 아니라 출전권 배분 기준이며, 설계 전반이 **정확성보다 감사 가능성과 납득 가능성**을 우선한다.

## 2. 핵심 요구사항

- **시작·종료 시각이 모두 명확할 것.** 사후 신고가 아니라 그 시각의 재실 증명에 근거해야 한다.
- **앱 설치 없이 동작할 것.** iOS/Android 모두. 전용 앱은 배포 마찰(App Store 심사, TestFlight 90일 만료, APK 사이드로드)이 규모에 비해 과도하다.
- **로그인이 유지될 것.** 스터디마다 재로그인은 불가.
- **구글 계정이 학번·이름·세부팀에 매핑될 것.**
- **개인 시간은 전원에게 공개될 것.** 본인의 엔트리 순위를 스스로 확인할 수 있어야 한다.
- 기존 예약 앱의 인증·배포·DB를 재사용해 인프라 추가 작업을 0으로 만든다.

## 3. 채택하지 않은 방식과 이유

| 방식 | 기각 사유 |
|------|-----------|
| BLE 비컨 + 웹 | iOS Safari가 Web Bluetooth 미지원. Android도 광고 스캔이 실험 플래그 뒤. 네이티브 앱 전제 기술 |
| ESP32가 폰을 BLE 스캔 | iOS/Android 모두 광고 MAC을 랜덤화해 개인 식별 불가 |
| 동방 Wi-Fi 접속 여부 | `heven` Wi-Fi는 내부 컴퓨터용. 팀원 폰이 접속하지 않음 |
| GPS 위치 | 실내 오차 30~60m로 방 단위 판별 불가. 브라우저 개발자도구에서 위조가 클릭 두 번 |
| PN532 NFC 카드 에뮬레이션 | iPhone이 에뮬레이션 태그를 안정적으로 인식하지 못함 |
| NTAG 424 DNA 스티커 | 유효한 대안이나 QR 대비 이점 없음. 무전원이 필요한 추가 방이 생기면 재검토 |
| RFID 카드 키오스크 | 카드 UID 사전 등록 필요, UID 복제 가능, 조립·유지보수 부담 |

**QR을 채택한 이유**: 모든 폰의 기본 카메라가 앱 없이 읽는다. 부품이 동방 재고(ESP32 + ILI9341)로 충당된다. 그리고 장비가 죽으면 화면이 꺼져 **고장이 눈에 보인다** — 유지보수 담당이 없는 동아리방 장비에서 이 성질이 중요하다.

## 4. 시스템 구성

```
[ESP32 + 2.4" ILI9341]  --60초마다 QR 갱신-->  (기본 카메라로 스캔)
        |                                              |
        | Wi-Fi(heven): NTP + 하트비트                  v
        +------------------------------->  [dongbang-booking / 젯슨 omo]
```

장비 2대: 공학실습동(24214), 학생회관(03324). 장비별 시크릿이 다르므로 서버가 어느 방인지 자동 판별한다.

예약 앱에는 공작실(24112A)이 세 번째 방으로 존재하지만 공학실습동 동방과 붙어 있어 장비를 따로 두지 않는다. 공작실 작업은 24214 장비로 체크인하며, **방 기록은 장비 기준이므로 공학실습동으로 집계된다.** 방별 통계를 볼 때 이 점을 감안한다.

**ESP32의 책임은 QR 표시 하나뿐이다.** 체크인 판정·기록·정책은 전부 서버가 한다. 정책 변경이 펌웨어 재배포를 유발하지 않게 하기 위한 경계다.

### 하드웨어

- LOLIN D32 (ESP32) + 2.4인치 ILI9341 240×320 SPI (동방 재고)
- 둘 다 3.3V — 레벨시프터 불필요. 클러스터 작업의 TFT_eSPI 설정 재사용
- 배선 8가닥: VCC / GND / CS / RST / DC(RS) / SDI / CLK / LED
- 24시간 상시 USB 전원. 백라이트는 GPIO 연결(심야 소등 여지)
- 모듈의 SD 슬롯은 미사용

### 화면 (240×320 세로)

방 이름 / QR 약 200×200 / "기본 카메라로 스캔" / 현재 재실 인원 · 시각.

"기본 카메라로 스캔" 문구는 필수다. 카카오톡 QR 스캐너는 인앱 웹뷰를 띄우는데 쿠키 저장소가 분리되어 매번 재로그인이 발생한다. iOS 기본 카메라는 Safari로, Android 기본 카메라/렌즈는 Chrome Custom Tab으로 열려 평소 세션을 공유한다. 웹앱도 인앱 브라우저를 감지하면 "외부 브라우저로 열기" 배너를 띄운다.

## 5. QR 코드 스킴

- 코드 = `HMAC-SHA256(장비별 시크릿, 60초 슬롯 번호)`의 앞 6자리 (TOTP와 동일 원리)
- **ESP32는 서버에 코드를 보고하지 않는다.** 서버가 같은 계산을 재현하므로 네트워크 왕복도 코드 저장소도 불필요하다. Wi-Fi는 NTP와 하트비트에만 쓰인다
- 서버는 **현재 슬롯과 직전 슬롯을 모두 인정**한다(실질 유효 60~120초). 카메라 조준 중 코드가 바뀌어 실패하는 것을 막는다
- 서버는 장비 2대 × 슬롯 2개 = 후보 4개를 대조한다. URL에 방 정보를 넣지 않아 QR이 짧게 유지된다
- **소각은 (코드, 멤버) 쌍 단위.** 여러 명이 같은 QR을 동시에 스캔하는 것은 정상 동작이다
- URL은 짧게: `{SITE_URL}/c/AB3K9F`. QR 모듈 수가 줄어 스캔 성공률이 오른다

### 로그인 전 스캔 (pending scan)

코드 유효시간이 60~120초라 미로그인 상태에서 구글 OAuth를 왕복하면 만료된다. 따라서:

1. URL 진입 즉시 코드를 검증하고 `pending_scan`으로 보관 (TTL 10분)
2. 로그인·온보딩 완료 후 해당 pending을 소비
3. **재실 증명 시각은 스캔 시각으로 기록한다** (로그인 완료 시각이 아님)

최초 온보딩이 1분 걸려도 시간이 깎이지 않는다.

## 6. 신원 — 학번 바인딩

**최초 로그인 직후 강제 온보딩.** 설정 탭 방식은 기각한다. 신원 미확정 상태의 세션이 쌓이면 소급 정리 비용이 크고, 설정 탭은 현실적으로 아무도 들어가지 않는다. pending scan 설계 덕분에 문 앞에서 시간 손해가 없으므로 강제해도 부담이 없다.

**흐름**: 학번 입력 → 원장 조회 → "김도현 · 토크 벡터링, 맞나요?" 확인 → 구글 계정에 영구 바인딩.

- 학번 원장(`2026년 1학기 헤븐 활동 회원 명부.xlsx`)과 스터디 시트(이름·세부팀)를 이름으로 조인해 시드한다. 조인 안전성은 아래에서 검증됨
- 진위 검증은 불가능(학교 인증 없음)하므로 **유일성만 강제**한다. 이미 클레임된 학번은 거부하고 관리자 문의로 보낸다. 확인 화면에 이름이 표시되고 선점이 잠기므로 사칭은 즉시 드러난다
- 원장에 없는 사람은 직접 입력 경로로 빠지되 체크인은 허용하고 `승인 대기`로 표시한다. 문 앞에서 막히는 사람이 없어야 한다
- 수정은 설정 탭에서 가능하되 **이름·학번 변경은 관리자 승인** 필요(누적 시간 이관 사고 방지)
- `@g.skku.edu` 강제는 하지 않는다. 개인 지메일 사용자가 배제되고 학번 진위가 검증되지도 않는다

### 시드 범위

**세부팀이 배정된 전기팀원 58명만 시드한다.**

명부(소속팀=전기, 62명)와 스터디 시트(세부팀)를 이름으로 조인해 세부팀이 있는 행만 넣는다. 세부팀 분포: 토크 벡터링 18 · 계기 및 데이터 14 · 배터리 및 전원 14 · 배선 및 하네스 12.

스터디 시트는 **최신본을 쓴다**. 리포지토리의 `2026/2026 스터디 참여시간.xlsx` 사본은 5월 4일자로 오래되어 인원이 한 명 적다(2026-08-21 기준 최신본은 8월 12일자).

제외되는 5명:

- 임원 `곽효건`(전기팀PL) · `김도현`(전기팀PM) · `박지원` — 엔트리 시간 산정 대상이 아니다
- 미활동 회원 `유상훈` · `이송헌`

세부팀이 `null`인 멤버가 존재하지 않으므로 온보딩에 세부팀 선택 단계는 없다. 시드에 없는 사람이 로그인하면 6절의 `승인 대기` 경로로 처리되며, 필요해지면 관리자가 편입한다(신입 부원, 임원이 나중에 기록을 원하는 경우).

전기 외 소속(기계·자율차)은 시드하지 않는다.

### 개인정보 취급

- 학번 원장 파일은 repo에 커밋하지 않는다(`.gitignore`). 시드는 로컬에서 1회 실행해 젯슨 SQLite에만 적재
- **명부의 `연락처`(휴대전화번호)는 시드하지 않는다.** 이 시스템에 필요 없는 정보다. 학과·학기·복수전공도 제외하고 이름·학번·소속팀·세부팀만 적재
- 학번은 본인과 관리자에게만 노출. 공개 목록에는 이름만 표시

### 세션 유지

- Auth.js JWT 세션 `maxAge` 1년, `updateAge` 1일(롤링 갱신). 주 1회 방문으로도 유지된다
- 쿠키는 서버가 `Set-Cookie`로 httpOnly 발급하므로 iOS Safari ITP의 7일 만료(JS 설정 쿠키 대상) 대상이 아니다

## 7. 세션 생명주기

### 증명 등급

| 등급 | 조건 | 처리 |
|------|------|------|
| **QR 종료** | 시작·종료 모두 QR 스캔 | 자동 승인 |
| **보정 신고** | QR 없이 종료 | 시간 인정하되 플래그, 관리자 승인 대기 |
| **미확정** | 종료 없이 10시간 초과 | 자동 마감 후 본인 신고 → 관리자 승인 |

QR 종료를 강제하면 이미 나간 사람이 종료를 못 해 데이터가 썩고, 아무 제약이 없으면 집에서 눌러 시간을 부풀릴 수 있다. **두 경로를 모두 열되 등급을 나누는 것**이 이 설계의 핵심이다. 부정은 눈에 보이게 되고 편의는 죽지 않는다.

### 10시간 룰

**종료 QR 없이 자동 마감된 세션에만 적용한다.** 정상적으로 QR을 찍고 나간 긴 세션은 10시간을 넘어도 유효하다. 대회 준비 기간의 실제 밤샘 작업까지 무효화하면 시스템 신뢰가 무너지기 때문이다. 이 규칙은 "장시간 작업"이 아니라 "종료 깜빡함"만 겨냥한다.

미확정 세션은 기록으로 남되 집계에서 제외되며, 본인이 종료 시각을 신고하고 관리자가 승인하면 복원된다.

### 체크아웃 누락 억제

- 체크인 상태면 어느 페이지를 열든 상단에 "스터디 중 · 3시간 12분 · [종료]" 고정 표시
- 세션 목록에 증명 등급 배지를 상시 노출
- 순위표에 보정 세션 비율 표시 (자정 작용)
- (선택, 후순위) PWA 홈화면 추가 사용자 대상 4시간 경과 웹푸시

### GPS의 역할

자동 승인 수단으로 쓰지 않는다. **보정 신고 시 위치를 첨부**해 관리자 판단 재료로만 사용한다. 사람이 최종 승인하는 경로이므로 위조 가능성이 문제가 되지 않는다.

## 8. 데이터 모델 (기존 스키마에 추가)

| 테이블 | 컬럼 요지 |
|--------|-----------|
| `member` | 학번(unique) · 이름 · 세부팀 · 구글계정ID(unique, 클레임 전 null) · 상태(active/pending/inactive) |
| `study_session` | member · room · 시작시각 · 종료시각(null=진행중) · 시작증명등급 · 종료증명등급 · 마감사유 |
| `used_code` | (코드슬롯, member) 소각 기록 — 재사용 차단. 만료분 주기 정리 |
| `pending_scan` | 랜덤 id · 코드슬롯 · 스캔시각 · 소비여부 (TTL 10분) |
| `session_edit` | 세션 · 수정자 · 수정시각 · 변경 전/후 · 사유 |
| `device_heartbeat` | 장비 · 최종수신시각 · 펌웨어버전 |

`session_edit`을 분리하는 이유: 여기서 시간은 출전권 배분 기준이다. **원본 시각을 덮어쓰지 않고 조정을 별도 행으로 쌓아야** 분쟁에 답할 수 있다.

기존 `reservations` 테이블은 `user_email` / `user_name` / `team`을 자유 텍스트로 갖는다. `member`가 생긴 뒤 예약의 팀 정보를 이 테이블로 역참조하도록 정리할 여지가 있으나 본 설계 범위 밖이다.

- GitHub식 잔디 그래프 (최근 26주, 단일 색 농담 램프)
- 최근 세션 목록 + 증명 등급 배지
- **본인 기록의 수정 이력**(수정자·사유 포함)을 본인이 열람 가능

### 순위표 (1급 화면)
엔트리 순서 결정 근거이므로 별도 화면으로 둔다.
- 전체 공개 개인 순위, 본인 위치 강조
- **엔트리 정원 컷 라인 표시**, 앞뒤 인원과의 격차
- 주간 인정 상한 적용 시 **상한 전/후 시간을 병기** (깎인 이유가 납득되어야 함)
- 보정 세션 비율 표시
- 보정 승인 이력은 공개 기록

### 팀 히트맵
세부팀 4개를 **스몰 멀티플로 분리**한다. 하나의 그리드에 팀 색을 섞으면 셀 색이 "어느 팀"과 "몇 시간"을 동시에 표현하게 되어 둘 다 읽히지 않는다. 팀마다 자기 색의 농담 램프를 주고 나란히 배치하면 팀 내부는 농도로, 팀 간은 패턴 모양으로 비교된다.

색상(라이트 테마 고정, 예약 앱과 동일):

| 세부팀 | hex |
|--------|-----|
| 계기 및 데이터 | `#2a78d6` |
| 배터리 및 전원 | `#eb6834` |
| 배선 및 하네스 | `#1baf7a` |
| 토크 벡터링 | `#4a3aa7` |

이 4색은 색각 이상 시뮬레이션을 포함한 전 조합 분리도 검증을 통과한 조합이다. 각 그래프에 팀 이름이 항상 붙으므로 색만으로 구분해야 하는 상황은 발생하지 않는다.

### 관리자 뷰
- 보정 신고 / 미확정 세션 승인 큐
- 학번 바인딩 해제, 승인 대기 멤버 편입
- 장비 상태(하트비트) 및 오프라인 알림
- 주간 인정 시간 상한 설정
- 기존 xlsx 형식으로 내보내기 (운영 이관 마찰 제거)

## 10. 실패 모드

| 상황 | 처리 |
|------|------|
| ESP32 전원/Wi-Fi 장애 | 하트비트 끊김 → 관리자 알림. 해당 구간의 보정 신고를 **"장비 장애" 태그로 자동 분류**해 승인 판단을 돕는다 |
| NTP 동기화 실패 | **QR을 띄우지 않고** "시각 동기화 실패 — 보정 신고로 기록해주세요" 표시. 틀린 QR을 띄우면 반복 실패로 신뢰를 잃는다. 부팅 시 필수, 1시간마다 재동기화 |
| 인앱 브라우저 진입 | 감지 후 "외부 브라우저로 열기" 배너 |
| 미로그인 스캔 | pending scan으로 보관, 스캔 시각 보존 |
