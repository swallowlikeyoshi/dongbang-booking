# 스터디 QR 표시 장비

LOLIN D32 + 2.4" ILI9341(240×320) SPI. 60초마다 서명된 6자리 코드를 QR로 표시한다.

## 디스플레이 — ILI9225 (ILI9341 아님)

**11핀 헤더 + `74HC245D` + `CMA30S`/`TnG1822E` 마킹인 빨간 모듈은 ILI9225 다.**
겉모습이 흔한 ILI9341 모듈과 거의 같아 혼동하기 쉽지만, ILI9341 라이브러리로
초기화하면 컨트롤러가 명령을 이해하지 못해 **백라이트만 켜진 흰 화면**이 된다.
전원·배선을 아무리 바꿔도 증상이 똑같으므로 전원 문제로 오인하기 쉽다.

구분법:

| 단서 | ILI9225 (이 모듈) |
|---|---|
| 헤더 | 11핀 `VCC · GND · GND · NC · NC · LED · CLK · SDI · RS · RST · CS` |
| 칩 마킹 | `74HC245D`(레벨시프터) · `CMA30S`/`TnG1822E` |
| 해상도 | **176x220** (ILI9341 은 240x320) |
| 라이브러리 | `Nkawu/TFT_22_ILI9225` (PlatformIO 레지스트리에 없어 GitHub URL 직접 지정) |

`tft.begin()` 후 `maxX()/maxY()` 가 176x220 으로 나오면 제대로 인식된 것이다.
ILI9341 라이브러리는 하드웨어 응답과 무관하게 설정값(240x320)을 그대로 읊으므로
그 숫자만으로는 인식 여부를 알 수 없다.

> 출처: 노션 「6/24 스터디 — ESP32 TFT LCD + CAN 버스 통합」(곽효건, 2026-06-24).
> 같은 모듈로 같은 증상을 겪고 해결한 기록이 이미 있었다.
> **새 하드웨어에서 막히면 노션을 먼저 검색하라.**

## 배선

핀 번호는 `src/config.h` 에 있다(빌드 플래그가 아니라).

| 모듈 실크 | ESP32 | 비고 |
|---------|-----------|---|
| VCC | **5V** | CMA30S 레귤레이터가 5V 입력을 요구한다 |
| GND | GND | |
| LED | 3V3 | |
| CLK | GPIO18 | VSPI 기본값 |
| SDI | GPIO23 | VSPI 기본값 |
| RS (= D/C) | GPIO21 | |
| RST | GPIO27 | **GPIO2 금지** — 부트스트랩 핀 |
| CS | GPIO22 | **GPIO15 금지** — 부트스트랩 핀 |
| NC | 연결하지 않음 | |

**GPIO0 · GPIO2 · GPIO15 는 부트스트랩 핀이라 TFT 제어에 쓰면 안 된다.**
GPIO2 를 RST 에 쓰면 부팅 시 LOW 로 유지되어 디스플레이가 리셋 상태에 걸리고,
역시 흰 화면이 된다.

GND 와 NC 가 두 개씩 연속이라 위치로 세면 밀린다. 반드시 실크 라벨을 보고 꽂는다.

### QR 크기

176x220 은 좁아서 QR 버전이 곧 스캔 거리다.

| URL 길이 | 버전 | 모듈 | 화면상 크기 |
|---|---|---|---|
| ~53자 | 3 | 29 | 174px (모듈당 6px) |
| 54~78자 | 4 | 33 | 165px (모듈당 5px) |

현재 URL 은 43자로 버전 3 이다. **`BASE_URL` 을 늘려 53자를 넘기면 버전이 올라가
QR 이 오히려 작아진다.** 도메인을 바꿀 때 주의한다.

### 라이브러리 주의

`TFT_22_ILI9225` 는 5인자 생성자의 마지막 인자를 LED 핀으로 해석한다.
SPI 클럭을 넘기려다 경고가 나므로 **4인자 하드웨어 SPI 생성자**를 쓴다.
소프트웨어 SPI(bit-bang)는 화면 갱신이 눈에 띄게 느리다.

```c++
TFT_22_ILI9225 tft = TFT_22_ILI9225(PIN_TFT_RST, PIN_TFT_DC, PIN_TFT_CS, (uint8_t)0);
```

### 화면이 안 나올 때

```bash
pio run -e diag -t upload      # 색 순환 + 해상도 출력
```

- `begin 완료 — 176x220` 이 뜨고 색이 순환하면 정상이다.
- 흰 화면만 계속되면 아래를 순서대로 본다.

| 확인 | 방법 |
|---|---|
| 컨트롤러 종류 | 칩 마킹과 핀 수. ILI9341 라이브러리로는 이 모듈이 절대 켜지지 않는다 |
| 부트스트랩 핀 | RST/CS 에 GPIO2·GPIO15 를 쓰고 있지 않은지 |
| VCC | 5V 인지. 3.3V 면 내부 레일이 부족해 컨트롤러가 동작하지 않는다 |
| 헤더 냉납 | 11핀을 인두로 다시 녹인다 |

## 빌드

```bash
cp src/config.h.example src/config.h   # 값을 채운다
pio run -t upload
pio device monitor
```

`DEVICE_SECRET` 은 서버 `.env` 의 `ATTENDANCE_DEVICE_SECRETS` 에 `방번호:시크릿` 형태로 등록한 값과 같아야 한다.

## 동작

- 부팅 시 Wi-Fi 접속 후 NTP 동기화. 실패하면 QR 대신 "TIME SYNC FAILED"를 띄운다.
  틀린 QR을 띄우면 반복 실패로 신뢰를 잃기 때문에 아무것도 띄우지 않는 쪽을 택했다.
- 1시간마다 NTP 재동기화(RTC 없음).
- 5분마다 하트비트를 보내고 응답의 재실 인원을 하단에 표시한다.

## 화면 텍스트가 전부 영문인 이유

TFT_eSPI에 기본 내장된 폰트는 ASCII 전용이라 한글 글리프가 없다. 한글 VLW 폰트 서브셋을
생성해 끼워 넣는 빌드 단계는 이번 계획 범위 밖이라, 화면에 그리는 문자열은 전부 ASCII로
바꿨다(`ROOM_NAME "24214"`, `"Scan with camera app"`, `"TIME SYNC FAILED"` /
`"Report manually"`). "기본 카메라로 스캔" 같은 한글 안내는 화면 옆에 붙이는 인쇄 라벨로
대체하는 것을 전제로 한다. 한글 VLW 폰트를 만들어 화면에 직접 표시하는 것은 추후
개선 과제로 남겨둔다.
