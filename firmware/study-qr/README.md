# 스터디 QR 표시 장비

LOLIN D32 + 2.4" ILI9341(240×320) SPI. 60초마다 서명된 6자리 코드를 QR로 표시한다.

## 배선

핀 번호는 `src/config.h` 에 있다(빌드 플래그가 아니라). 배선이 다른 장비를 만들면 그 파일만 고친다.
아래 값은 클러스터 PCB(HEVEN `firmware/cluster` **origin/main**)에서 실물 검증된 배정이다.

| 모듈 실크 | ESP32 |
|---------|-----------|
| VCC | **5V** (아래 "모듈 전원" 참조) |
| GND | GND |
| CS | GPIO4 |
| RST | GPIO16 |
| RS (= D/C) | GPIO5 |
| SDI (= MOSI) | GPIO19 |
| CLK (= SCK) | GPIO21 |
| LED | 3V3 직결 |
| NC | 연결하지 않음 |

주의할 점 두 가지.

- **SCK/MOSI 가 기본 VSPI 핀(18/23)이 아니다.** ESP32 는 GPIO 매트릭스로 아무 핀에나
  SPI 를 붙일 수 있어 동작에는 문제가 없지만, "SPI 니까 18/23" 이라고 짐작하면 어긋난다.
- **실크의 `RS` 가 D/C 다.** `RST` 와 이름이 비슷해 바꿔 꽂기 쉬운데, 이 둘이 바뀌면
  백라이트만 켜진 백색 화면이 되고 다른 증상은 전혀 나오지 않는다.

흔한 2.4/3.0인치 빨간 모듈은 헤더가 11핀이고 순서가
`VCC · GND · GND · NC · NC · LED · CLK · SDI · RS · RST · CS` 다.
GND 와 NC 가 연속으로 두 개씩 있어 위치로 세면 밀린다. 반드시 실크 라벨을 보고 꽂는다.

### 모듈 전원 — 3.3V 를 넣으면 안 된다

이 모듈에는 **74HC245 레벨 시프터(U2)** 와 **3.3V LDO(U1)** 가 올라가 있다.
설계 의도는 `VCC(5V) → LDO → 3.3V → 245 + ILI9341` 이다.

VCC 에 3.3V 를 넣으면 LDO 드롭아웃 때문에 내부 레일이 2V 대로 떨어져 컨트롤러가
명령을 실행하지 않는다. **백라이트는 Q1 을 통한 별도 경로라 멀쩡히 켜지므로**,
"불은 들어오는데 아무것도 안 그려지는" 상태가 되어 전원 문제로 보이지 않는다.

`J1` 은 LDO 우회 점퍼다. **열림 = LDO 경유(5V 입력용, 정상)**, 납으로 이으면
VCC 가 내부 3.3V 레일에 직결된다. J1 을 이은 상태에서 5V 를 넣으면 245 와
ILI9341 이 5V 를 그대로 받아 손상된다.

또한 이 모듈에는 SDO(MISO) 가 나와 있지 않다. 컨트롤러 ID 를 읽어 확인하는
진단은 쓸 수 없고, 아래 색 순환으로만 판별해야 한다.

### 라이브러리

**Adafruit_ILI9341 + Adafruit_GFX 를 쓴다.** TFT_eSPI 는 핀 설정을 컴파일 타임
매크로로 주입하는 구조라 조용히 어긋나기 쉽다. 클러스터 펌웨어가 Adafruit 경로로
같은 패널을 구동하는 것이 실물로 확인되어 있어 그쪽에 맞췄다.

패널 색이 반전되어 보이면 `config.h` 의 `TFT_INVERT` 주석을 해제한다.
QR 은 반전되어도 대부분의 스캐너가 읽지만 가독성은 떨어진다.

### 화면이 안 나올 때

진단 스케치가 `config.h` 의 핀을 그대로 써서 GPIO 되읽기와 색 순환을 돈다:

```bash
pio run -e diag -t upload
```

- **색이 순환하면** SPI 경로는 정상이므로 애플리케이션 코드 문제다.
- **계속 백색이면** 아래 순서로 좁힌다. 실제로 이 순서로 원인을 찾은 적이 있다.

| 확인 | 방법 |
|---|---|
| VCC 가 5V 인가 | 모듈 헤더의 VCC–GND 를 직접 측정. 전선·핀을 믿지 않는다 |
| 내부 3.3V 레일 | U1 옆 C1 양단. 3.2~3.3V 가 정상. 3.0V 이하로 처지면 뒷단 과전류를 의심 |
| 칩 발열 | 5V 인가 후 30초, U2 와 컨트롤러 부위를 만져본다. 따뜻하면 부분 단락 |
| 헤더 냉납 | 11핀을 인두로 다시 녹인다 |
| 모듈 자체 | 동작이 확인된 다른 모듈로 교체해 본다 — 이게 가장 빠른 판별이다 |

보드·라이브러리·SPI 속도·핀 배정을 아무리 바꿔도 백색이면 모듈 불량일 가능성이 높다.
실제로 보드 2종 · 라이브러리 2종 · 40/20/4MHz · 핀 3조합 · 3.3V/5V 를 모두 시도한 끝에
모듈 교체로 해결된 사례가 있다. **동작이 확인된 모듈로 바꿔보는 것을 일찍 시도하라.**

## 빌드

```bash
cp src/config.h.example src/config.h   # 값을 채운다
pio run -t upload
pio device monitor
```

`DEVICE_SECRET` 은 서버 `.env` 의 `ATTENDANCE_DEVICE_SECRETS` 에 `방번호:시크릿` 형태로 등록한 값과 같아야 한다.

## 동작

- 부팅 시 Wi-Fi 접속 후 NTP 동기화. 실패하면 QR 대신 "TIME SYNC FAILED"를 띄운다.
  틀린 QR을 띄우면 반복 실패로 신뢰를 잃기 때문에 아무것도 띄우지 않는 쪽을 택했다.
- 1시간마다 NTP 재동기화(RTC 없음).
- 5분마다 하트비트를 보내고 응답의 재실 인원을 하단에 표시한다.

## 화면 텍스트가 전부 영문인 이유

TFT_eSPI에 기본 내장된 폰트는 ASCII 전용이라 한글 글리프가 없다. 한글 VLW 폰트 서브셋을
생성해 끼워 넣는 빌드 단계는 이번 계획 범위 밖이라, 화면에 그리는 문자열은 전부 ASCII로
바꿨다(`ROOM_NAME "24214"`, `"Scan with camera app"`, `"TIME SYNC FAILED"` /
`"Report manually"`). "기본 카메라로 스캔" 같은 한글 안내는 화면 옆에 붙이는 인쇄 라벨로
대체하는 것을 전제로 한다. 한글 VLW 폰트를 만들어 화면에 직접 표시하는 것은 추후
개선 과제로 남겨둔다.
